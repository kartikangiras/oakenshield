How it works

The argument ends where the experiment starts

An agent can write three versions of a screen in a minute and argue well for every one of them. Arguing does not settle which is better, so a duel hands the question to visitors.

  1. 1

    The agents argue

    Two agents get the same brief and opposite convictions. Each writes its own version, a hypothesis in one sentence and a prediction, attacks the other's version and may revise its own once.

  2. 2

    An experiment decides

    Both versions run against today's in one Flagsmith experiment with three versions. The run is sealed, and the verdict is read once, by a rule fixed before the start.

  3. 3

    A person approves

    The agents hold no Flagsmith credentials. Nothing starts and nothing ships without a person's yes, given on their own terminal.

The eight steps, and who does each

  1. 1The briefA personWrites one goal, the one event that counts, and a fact sheet: everything a version is allowed to claim.
  2. 2Two proposalsThe agentsEach writes a version, a hypothesis in one sentence and a predicted result for all three versions.
  3. 3Cross examinationThe agentsEach attacks the other's version, concedes what it does better and may revise its own once. The transcript is kept.
  4. 4Referee checkThe refereeRejects a version that drops, renames or doubles the measured event, or claims something the fact sheet does not support.
  5. 5Start approvedA personNothing exists in Flagsmith until now. The person confirms on their own terminal and passes an approval code.
  6. 6The experimentFlagsmithOne flag, three versions: today's as control and one variation per agent, whose value is that agent's whole version.
  7. 7The verdictThe refereeRead once, when every version has its planned sample. "Neither beats today's" is a valid answer.
  8. 8Rollout approvedA personA second yes. Flagsmith completes the experiment with the winner and the flag serves it to everyone in that environment.

Steps 5 to 8 are the flagsmith-duel skill's script, which does every Flagsmith read and write through the Flagsmith CLI.

Who decides

What the agents do alone, and where a person decides

Everything the agents do alone can be thrown away or repeated. Everything a person decides changes what visitors see or what the result means.

Done without asking

  • Writing the versions, the hypotheses, the attacks and the predictions
  • Checking the plan against Flagsmith, which only reads
  • Auditing the running experiment against the seal, as often as wanted
  • Counting visitors, and reading the result once when the sample is in

Decided by a person

  • The brief: the goal, the event that counts, what may be claimed
  • The start
  • Stopping a run early
  • The rollout, and whether the losing version is removed
An approval code
The plan prints what the start would create, and a code. The code is a digest of the flag, the environment, the split, each version's contents, the events and the rule. Change any of them and the code no longer matches.
The person's own terminal
A protected environment also needs approve, which refuses to run unless a terminal is attached, which an agent's shell is not. The person types the environment's name.
No credentials for the agents
The two agents run with no tools at all. What they produce is text that the referee parses.

Three guards

Three guards keep the run honest

A duel can go wrong in three places: in what an agent writes, in Flagsmith while the experiment runs, and in the code the experiment depends on. Each has its own guard.

  • Before the start

    The screen referee

    Stops an agent from winning by cheating. It rejects a version with no check button or two of them, a button that checks a different pull request from the one shown, markup, web addresses, or a claim the fact sheet does not support.

  • During the run, in Flagsmith

    The seal and the audit

    The start writes a seal: the experiment, the split, the metrics and a hash of every version's contents. The audit compares Flagsmith with the seal and reports a changed split, an edited, deleted, added or renamed version, changed metrics, a changed audience or a pause.

  • During the run, in the code

    Experiment Guard

    Blocks a pull request that changes the code the experiment depends on while it runs: the event renamed, the exposure call removed, and eleven more rules.

Why the seal exists

We expected Flagsmith to lock a running experiment. When we tested Flagsmith Cloud on 27 November 2026, its Admin API accepted a change of split, an edit to a version's value and the deletion of a version while an experiment was running, and a paused experiment went on serving every version. So the lock is the duel's own: the verdict and the rollout refuse while the seal is broken.

Experiment Guard has thirteen rules, and only the provable ones block

It reads the experiments running in Flagsmith, reads the pull request, and blocks the merge when the change breaks what an experiment measures or serves.

Run against the duel while experiment 1497 was running, it blocked a rename of check_run with three findings of rule EG001, one for each place the dashboard sends the event, and a removed exposure call with rule EG002.

Agent Skill

The same job for any coding agent and any flag

flagsmith-duel is the duel's Flagsmith half as an Agent Skill: one job from plan to rollout, on the Flagsmith CLI. A version's value is any text or JSON, so it settles a disagreement about a message, a price or a setting the same way.

/plugin install flagsmith-duel --marketplace kartikangiras/oakenshield

Works in Claude Code 2.1.275 or later. Needs the Flagsmith CLI 2.0 or later, Node 20 or later and git.

FAQ

Questions worth asking first

Are the visitors real people?

No. They are AI personas: Claude Haiku playing one invented person per visit, in a real browser, on the real built dashboard. Flagsmith picks the version and records the exposure, and the dashboard sends check_run only when a click really runs a check. A persona is never told what is measured, that there is an experiment or which version it got.

Is the result evidence about people?

No. A persona is a model's guess at a person, and the agents and the personas are the same model family, so a screen may win because it is written the way that family likes to read. The personas also click far more than people do. The run shows that the whole chain holds on a real Flagsmith experiment with three versions, and which screen a model reader prefers.

Do the agents have access to Flagsmith?

No. The two agents run with no tools and hold no credentials. Each one's whole output is one JSON object that the referee parses. Every Flagsmith read and write goes through one script on the Flagsmith CLI.

What stops an agent from starting or shipping on its own?

The start and the rollout each need an approval code, which is a digest of what the person was shown. A protected environment also needs the person to confirm on their own terminal by typing the environment's name. These approvals are a convention for an agent that follows its instructions. Against one that does not, keep the Flagsmith key out of its reach.

What if neither version beats today's screen?

Then today's screen stays. That is a valid answer, and the rule says so before the start. A version qualifies only above a 95% chance to beat today's screen on the goal, with its guardrail holding.

Does Flagsmith lock a running experiment?

Not when we tested Flagsmith Cloud on 27 November 2026. Its Admin API accepted a change of split, an edit to a version's value and the deletion of a version during a run. That is why the start writes a seal and the audit checks Flagsmith against it.

What does it need to run?

A duel needs the Flagsmith CLI 2.0, a Flagsmith organisation API key, Node 22.18 or newer, and Claude Code logged in for the agents and the personas. The skill on its own needs the Flagsmith CLI 2.0 or later, Node 20 or later and git.

What does this site record about me?

This page sends no events and keeps nothing in your browser. The dashboard keeps a random ID in your browser. If you run a check or copy a setup snippet there, that event goes to Flagsmith with the ID. Only a visitor who opens the dashboard with no page in the link is entered in an experiment, and every link on this page opens a named page.

Is it free and open source?

Yes. Oakenshield is open source under the MIT license. The code, the brief, the whole debate and the files of the run are in the repository on GitHub.
